1. Logging In

Navigate to the application URL. Enter your email address and password, then click Login. New users can register by clicking the Register tab and providing an email, name, and password.

Screenshot: Login page

2. Creating a Workflow via Chat

Type a description of your workflow in the chat panel on the left side of the screen. For example: "Create a diabetes treatment workflow that checks HbA1c levels and recommends medication adjustments." The orchestrator will build nodes and connections on the canvas in real time. You can see each tool call as it executes.

Screenshot: Chat panel with workflow being built on canvas

3. Uploading a Flowchart Image

Click the upload button (paperclip icon) in the chat input area. Select an image file (PNG, JPG) or PDF of a flowchart. The system will analyze the image and reconstruct it as an editable workflow on the canvas.

Screenshot: Image upload and reconstruction

4. Editing on the Canvas

Drag nodes to reposition them. Right-click a node to open its context menu (edit, delete, connect). Draw connections by clicking the output port of one node and dragging to the input of another. Use scroll wheel to zoom and click-drag on empty space to pan.

Screenshot: Canvas with nodes and connections

5. Managing Variables

Open the right sidebar to view workflow variables. Each variable has a name, type (string, number, boolean, date, enum), and optional description. Variables are used in decision conditions and calculation nodes. The orchestrator creates variables automatically, but you can also add or edit them manually.

Screenshot: Variable panel in sidebar

6. Using Subworkflows

Create a subprocess node to reference another saved workflow. Configure the input mapping to connect parent variables to the child workflow's inputs. When executed, the subprocess runs the referenced workflow and returns its output as a derived variable.

Screenshot: Subprocess node configuration

7. Executing with Test Inputs

Click the Execute button. Enter values for each input variable in the dialog that appears. Click Run to start execution. The system steps through each node, highlighting the active node and the execution path on the canvas. The final output and execution context are displayed when complete.

Screenshot: Execution dialog and path highlighting

8. Saving to Library

Click Save in the header to store your workflow in the personal library. You can access saved workflows later from the Library page (/library). Each workflow stores its full state including nodes, edges, variables, and conversation history.

Screenshot: Library page

9. Exporting

Navigate to the Export page. Choose your export format:

  • JSON: Complete workflow data including nodes, edges, variables, and metadata
  • Python: Compiled executable code that reproduces the workflow logic
  • PNG: Visual image of the workflow canvas
Screenshot: Export page with format options

Deployment Manual

Prerequisites

  • Python 3.10 or later
  • Node.js 18 or later
  • uv (Python package manager): install with curl -LsSf https://astral.sh/uv/install.sh | sh
  • An Anthropic API key (obtain from console.anthropic.com)

Local Development Setup

  1. Clone the repository:

    git clone https://github.com/jrh-mann/LEMON.git
cd LEMON

  2. Install Python dependencies:

    uv sync

  3. Install frontend dependencies:

    cd src/frontend
npm install
cd ../..

  4. Configure environment variables:

    cp .env.example .env

    Then edit .env and add your Anthropic API key:

    ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-opus-4-6

  5. Start the development servers:

    ./scripts/dev.sh

  6. Access the application:

    • Frontend: http://localhost:5173
    • Backend: http://localhost:5001
    • Logs: /tmp/lemon-backend.log, /tmp/lemon-frontend.log

Azure Deployment

The project uses GitHub Actions for production deployment. The workflow file is at .github/workflows/deploy-prod.yml.

Deployment process:

  1. Push code to the prod branch
  2. GitHub Actions automatically triggers the deployment workflow
  3. The workflow installs Node.js 20, builds the frontend (npm ci && npm run build)
  4. Packages the backend (src/backend, compiled frontend, scripts, configuration) into a ZIP archive
  5. Deploys to Azure Web App using the publish profile stored as a GitHub secret

To configure deployment for a new environment:

  • Set up an Azure Web App instance
  • Add the Azure publish profile as a GitHub repository secret named AZUREAPPSERVICE_PUBLISHPROFILE
  • Push to the prod branch to trigger deployment

GDPR and Data Privacy

LEMON stores workflow definitions, user accounts (email and hashed password), and conversation logs for audit purposes.

No patient data or personally identifiable health information is processed or stored by the system. The requirements specification explicitly excludes patient datasets and production data processing from the system scope.

Workflow descriptions and chat messages are sent to the Anthropic Claude API for processing. Anthropic's data handling and privacy policies apply to this transmitted data. Users should be informed that their input is processed by a third-party AI service.

User authentication uses PBKDF2 password hashing with random salts. Passwords are never stored in plaintext.

Users can delete their workflows at any time. Session tokens expire automatically.

The system enforces user ownership on all API endpoints, ensuring users can only access their own data.

December 9-15, 2025: Project Kickoff

Initial repository setup and exploration of the problem space. Early prototyping of the frontend and code generation pipeline, including a workflow executor and test harness. First experiments with LLM-based workflow refinement began.

January 7-14, 2026: Building the Foundation

Connected the frontend prototype to a new backend architecture. Switched from the initial LLM approach to Claude as the primary provider, taking advantage of its native tool-use API. Separated the backend into a standalone FastAPI service. Added workflow upload and image analysis capabilities.

January 15-20, 2026: The Visual Editor Takes Shape

Major canvas development sprint. Implemented drag-and-drop node positioning, collision detection to prevent overlapping nodes, a hierarchical auto-layout algorithm, connection drawing between nodes, and color-coded node types. Added a node palette for creating nodes manually and JSON import for loading existing workflows.

January 21-29, 2026: Workflow Execution Engine

Built the expression parser and evaluator for decision node conditions. Implemented the TreeInterpreter for walking workflows and producing execution results. Added the validation framework for checking workflow correctness before save or export. Expanded the tool system to over 20 tools. Added subprocess nodes and compound conditions.

February 3-11, 2026: Scaling Up

Intensive development period. Built end-to-end test infrastructure using Playwright. Added workflow library features for saving and browsing workflows. Implemented prompt caching to reduce API costs on repeated interactions. Added task cancellation and conversation state management for long-running orchestrator sessions.

February 20-27, 2026: Subworkflows and Streaming

Implemented independent subworkflow builders with recursive execution and input/output mapping between parent and child workflows. Built the SSE infrastructure for real-time event streaming. Added build depth limits to prevent infinite recursion. Improved frontend resilience with localStorage quota handling and event routing fixes.

March 1-9, 2026: Execution Controls and Tool Format

Rewrote end-to-end tests to run against a real backend instead of mocks. Switched the internal tool format from OpenAI-style to native Anthropic format. Added stepped execution with pause, resume, and stop controls.

March 10-16, 2026: Architecture Migration, Evaluation and Hardening

Completed the migration from Socket.IO to Server-Sent Events, simplifying the real-time communication infrastructure. Built the six-dimension evaluation framework for measuring workflow extraction quality (variables, nodes, topology, conditions, outputs, functional routing). Implemented comprehensive security hardening: XSS prevention, path traversal mitigation, CSRF headers, rate limiting, and user ownership enforcement on all API endpoints.
