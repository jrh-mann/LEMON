Conclusion

Project Summary

LEMON lets clinicians build executable decision workflows by describing them in plain language or uploading a flowchart image. An LLM orchestrator turns that input into a structured decision tree on a visual canvas. The finished system supports six node types, typed variables, compound conditions, subworkflows, and stepped execution with step-level debugging. Workflows can be exported as JSON, compiled Python, or PNG.

Goals Revisited

We set four product goals at the start of the project. Here is how each one played out.

Reduce the effort required to formalise expert decision logic. Users can describe a decision process in plain English or upload a photo, and the system produces a structured workflow. No code required.

Provide a safe authoring environment with strong validation before execution or export. The validation framework checks workflows before they can be run or exported, and stepped execution lets users walk through a workflow node by node to spot logic errors before anything goes live.

Support review, sharing, and reuse of high-value workflows. The workflow library lets users save, browse, and reload workflows. Users can publish workflows to a community gallery where others can browse them and vote on quality. Workflows that receive enough upvotes are promoted to "reviewed" status, surfacing the most trusted content.

Enable export to formats suitable for downstream engineering systems. Workflows export to JSON for interoperability, compiled Python for direct execution, and PNG for documentation or review.

Lessons Learned

Giving the LLM a fixed set of typed tools instead of asking it to generate free-form code turned out to be the right call. Every tool call can be validated against a schema, so errors get caught and handled rather than silently corrupting the workflow. This would not have worked with unconstrained generation.

Standard unit tests aren't enough when your system depends on an LLM. The 6-dimension scoring framework gave us actual numbers on how well the orchestrator was performing, so we could track regressions when we changed prompts or updated models.

Migrating from Socket.IO to SSE mid-project was disruptive but worth it. SSE was a better fit since we only needed one-way streaming, and it was much simpler to debug. Sometimes the right call is to rip something out and replace it even when it already works.

Closing Statement

LEMON shows that an LLM with well-defined tools can act as a reliable bridge between what a person means and what a computer needs. By keeping the interface conversational, workflow formalization becomes something a clinician can do without help from a developer. We think the same approach could work for other kinds of structured authoring beyond clinical workflows.
