Conclusion

Project Summary

LEMON is a conversational AI platform for clinical workflow authoring. Users describe decision logic in natural language or upload a flowchart image, and an LLM orchestrator translates that into a structured, executable decision tree on a visual canvas. The system supports six node types, typed variables, compound conditions, subworkflows, and stepped execution with step-level debugging. Completed workflows can be exported to JSON, compiled Python, or PNG.

Goals Revisited

The project was shaped around four product goals, each of which was addressed in the final system.

Reduce the effort required to formalise expert decision logic. Natural language input and image-based workflow creation remove the need for any technical expertise. A clinician can describe a decision process in plain terms and the system produces a structured workflow without the user writing a single line of code.

Provide a safe authoring environment with strong validation before execution or export. A structural validation framework checks workflows before they can be run or exported. Stepped execution lets users walk through a workflow node by node, inspecting state at each step and catching logical errors before deployment.

Support review, sharing, and reuse of high-value workflows. A workflow library allows users to save, browse, and reload workflows. This makes it practical to build on existing work rather than starting from scratch each time.

Enable export to formats suitable for downstream engineering systems. Workflows export to JSON for interoperability, compiled Python for direct execution, and PNG for documentation or review.

Lessons Learned

The tool-use architecture proved to be the right approach for this kind of system. Giving the LLM a small set of constrained, typed tools rather than asking it to generate free-form code meant that output could be validated against a schema at each step. Errors were contained and recoverable, which would not have been the case with unconstrained generation.

Testing LLM-integrated systems requires more than standard unit tests. The 6-dimension scoring framework built for LEMON provided quantitative feedback on orchestrator quality across real prompts, making it possible to track regression and improvement in a way that simple pass/fail tests could not.

The mid-project migration from Socket.IO to Server-Sent Events was a useful reminder that pragmatic decisions matter. SSE was a better fit for the unidirectional streaming pattern of LLM output, simpler to reason about, and easier to debug. Switching was disruptive in the short term but improved the overall architecture.

Closing Statement

LEMON demonstrates that LLM tool use can close the gap between domain expertise and executable logic. By keeping the authoring interface conversational and delegating structure to the orchestrator, the system makes workflow formalization accessible to people without programming skills. The core idea, that an LLM with well-defined tools can act as a reliable intermediary between human intent and machine-readable structure, holds up in practice and points toward a broader class of authoring tools worth building.
