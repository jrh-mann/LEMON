System Design

System Architecture

LEMON follows a layered architecture. The React frontend communicates with the FastAPI backend via REST API calls and receives real-time updates through Server-Sent Events. The backend orchestrates LLM interactions through a tool-use loop, with the Event Bus decoupling tool execution from the transport layer. Workflow execution is handled by a dedicated interpreter that evaluates conditions using a custom expression parser.

Design Patterns

Pattern Where Used Purpose
Observer EventBus (events/bus.py) Decouple tool execution from transport. Subscribers receive TOOL_STARTED, TOOL_COMPLETED events without knowing about SSE or the frontend.
Registry ToolRegistry (tools/core.py) Central catalog of 30+ tools. Generates JSON schemas for the LLM automatically. New tools are registered declaratively.
Interpreter TreeInterpreter (execution/interpreter.py) + Parser/Evaluator Walk the workflow tree at runtime, evaluate conditions, execute calculations. Classic interpreter pattern for a domain-specific language.
Factory OrchestratorFactory (agents/orchestrator_factory.py) Create configured Orchestrator instances with the correct tools, event bus, and session context for each chat interaction.

Data Storage

LEMON uses three separate SQLite databases to isolate concerns. Workflow data (definitions, votes, schema version) is kept in workflows.sqlite. Authentication data (users, sessions) is in auth.sqlite. Conversation history for audit purposes is in conversation_log.sqlite. The schema uses version-based migrations, currently at version 8.
